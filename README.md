# SNS 발행기 (snspub)

**나만 쓰는 최소 기능 SNS 예약 발행 프로그램.**
Buffer·Upload-Post·Ayrshare·Postiz·Meta 비즈니스 스위트를 분석해서, 실제로 쓰는 기능만 남겨 Mac mini 한 대에서 안정적으로 돌아가게 만들었습니다.

- 대상 채널: YouTube 쇼츠 · Instagram · Facebook 페이지 · TikTok · Threads · X · 네이버 클립 · 네이버 카페
- 콘텐츠: 완성된 쇼츠 영상(mp4) 1개, 또는 카드뉴스 이미지 묶음(폴더)
- 설치할 패키지 없음 (Node.js 만 있으면 됨), 데이터는 이 Mac 에만 저장

---

## 왜 새로 만들었나

2026-09-27 「SNS 자동업로드 구조 개선 보고서」의 진단: 기존 업로더는 **AI 브라우저가 매 단계를 대신 판단**하고 **한 번만 막혀도 전체가 멈추는 구조**라서 19일 동안 32번 멈췄고 공개 게시는 2건이었습니다.

이 프로그램은 그 반대로 만들었습니다.

| 기존 구조의 문제 | 이 프로그램 |
|---|---|
| AI 브라우저가 화면을 보고 판단 | **공식 게시 통로(API)만 사용** — 화면 조작 없음 |
| 한 채널이 막히면 전체 정지 | **채널마다 따로 실행** — 한 채널 실패가 다른 채널에 번지지 않음 |
| 실패하면 멈추고 사람이 재시작 | **연결 끊김·일시 장애만 자동 재시도** (1→5→15→30→60분) |
| 결과가 불분명해도 다시 시도 → 중복 위험 | **게시됐는지 모르면 절대 다시 올리지 않고 "확인 필요"로 멈춤** |
| 로그인 만료 시 전체 중단 | **그 채널만 보류**, 연결 확인이 통과하면 밀린 예약 자동 재개 |

## 한눈에 보기

```
수신함 폴더 ──▶ [새 발행] 채널·시간·채널별 문구 확인 ──▶ 발행 등록 (한 번 클릭)
                                                        │
          예약 시각이 되면 채널별로 따로 게시 ◀─────────────┘
          (YouTube 12:50 → Instagram 13:23 → … 채널 사이 25~40분)
                     │
     ┌───────────────┼──────────────────┬───────────────────┐
  게시 완료        일시 오류            결과 불확실          API 없는 채널
  (주소 기록)    → 자동 재시도        → "확인 필요"(멈춤)   → "직접 올릴 차례"
                                                           (업로드 도우미)
                     │
     선택한 채널이 모두 끝나면 원본을 보관 폴더(월별)로 이동
```

웹 화면(`http://127.0.0.1:4310`, 이 Mac 에서만 열림)

- **발행 현황** — 콘텐츠별 채널 상태, 게시 주소, 실패 이유와 버튼(다시 올리기·게시됨으로 표시·취소·지금 올리기·수정)
- **새 발행** — 수신함에서 콘텐츠 선택 → 기본 문구 → 채널·시작 시각 → 채널별 시각·문구 확인(글자 수 검사) → 발행 등록
- **채널** — 채널별 게시 경로와 연결 상태, 연결 확인·로그인 버튼
- **기록** — 모든 동작 기록

## 설치 (Mac mini)

터미널(응용 프로그램 → 유틸리티 → 터미널)에 아래 한 줄을 붙여 넣고 Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/dreamthinkerharvester/claude_Desktopapp/HEAD/install.sh | bash
```

설치 명령이 하는 일

1. 개발 도구(git)와 Node.js 22.13 이상 확인 (Node.js 가 없으면 Homebrew 로 설치)
2. `~/sns-publisher` 에 내려받기 (이미 있으면 최신으로 업데이트)
3. **설정 마법사** — 질문 4개
   1. Upload-Post API 키 (바로 확인하고, 연결된 SNS 계정을 보여 줌)
   2. 프로필 (여러 개일 때만)
   3. 요금제: 무료(월 10회, TikTok 제외) / 유료
   4. 수신함·보관 폴더 (Enter 면 `/Volumes/MacData/1. 최종콘텐츠/…` 기본값)
4. 채널 연결 확인 → 맥이 켜질 때 자동 실행 등록 → 브라우저에서 `http://127.0.0.1:4310`

같은 명령을 다시 실행하면 프로그램이 최신으로 바뀌고 설정 마법사가 다시 열립니다 (기존 값은 Enter 로 유지, 실행 중인 발행기는 새 설정으로 다시 켜짐).

- 외장 디스크(`/Volumes/...`)의 파일을 읽으려면 **시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한**에 node 를 추가해야 할 수 있습니다 (설치 끝에 경로를 알려 줍니다).
- 예약 시각에 Mac mini 가 켜져 있어야 올라갑니다. **시스템 설정 → 에너지 → "디스플레이가 꺼져 있을 때 자동으로 잠자기 방지"** 를 켜 두세요.
- 직접 설치하려면: `git clone https://github.com/dreamthinkerharvester/claude_Desktopapp.git ~/sns-publisher && cd ~/sns-publisher && node bin/snspub.js setup`

> `npm link` 를 한 번 해 두면 `node bin/snspub.js` 대신 `snspub` 으로 쓸 수 있습니다.

### Upload-Post 무료로 시험 → 유료 전환

1. <https://app.upload-post.com> 에서 **프로필**을 하나 만들고 YouTube·Instagram·Facebook(페이지)·Threads·X 를 연결합니다 (TikTok 은 유료 플랜에서).
2. **API Keys** 에서 키를 만든 뒤 위 설치 명령을 실행해 마법사에 붙여 넣고, 요금제는 `1) 무료`.
   - 무료에서는 TikTok 이 업로드 도우미(반자동)로 설정됩니다.
3. 무료 10회는 **채널 1곳에 1번 올릴 때마다 1회**입니다 (채널마다 요청을 따로 보내기 때문). 예) 영상 1개 × 5개 채널 = 5회 → 처음에는 영상 1개로 시험하세요.
4. 결과가 괜찮아 유료로 바꿨다면: 프로필에 TikTok 을 연결 → **설치 명령을 다시 실행** → 요금제 `2) 유료` → TikTok 도 자동 게시로 바뀝니다.

## 게시 경로 고르기

채널마다 `config.jsonc` 의 `channels.<채널>.route` 로 고릅니다. 카드뉴스만 다른 경로로 보내려면 `imagesRoute`.

| 경로 | 비용 | 준비 | 채널 | 비고 |
|---|---|---|---|---|
| `uploadpost` (**권장**) | 월 $24 (연간 결제 시 월 $16) | 가입 → 계정 연결 → API 키 | YouTube·TikTok·Instagram·Facebook·Threads·X | YouTube·TikTok 심사를 업체가 이미 통과. 로컬 파일을 그대로 올림. 무료 플랜은 월 10건·TikTok 제외 |
| `meta` | 무료 | Meta 앱(개발 모드) + 토큰 등록 | Instagram(영상), Facebook(영상·카드뉴스) | 페이지 토큰은 만료 없음. Instagram 카드뉴스는 API 가 공개 URL 만 받아 미지원 |
| `youtube` | 무료 | Google OAuth + **API 감사 통과** | YouTube 쇼츠 | 감사 전 업로드는 **비공개로 잠겨** 공개 전환 불가 → `audited: true` 전에는 올리지 않음 |
| `naver_cafe` | 무료 | 네이버 개발자 앱 + 로그인 | 네이버 카페 | 영상 업로드 API 없음 → 소개글 + 먼저 올라간 채널 링크 |
| `manual` | 무료 | 없음 | 모든 채널 (네이버 클립 필수) | 예약 시각에 알림 → [업로드 도우미]가 문구 복사·업로드 페이지·파일 위치를 열어 줌 → 올린 뒤 [완료] |

- **TikTok 은 개인용 앱으로는 공개 게시 심사를 받을 수 없습니다**(TikTok 정책: "본인·팀 계정 업로드 도구는 심사 대상 아님"). 자동으로 올리려면 `uploadpost`, 아니면 `manual`.
- **네이버 클립·블로그는 공개 API 가 없습니다** (블로그 글쓰기 API 는 2020-05-06 종료). 클립은 `manual`.

## 사용법

### 화면에서

1. **새 발행** → 수신함에서 영상/카드뉴스 폴더 선택
2. 제목(유튜브 제목·카페 글 제목), 소개글, 해시태그 입력
3. 채널 체크, "지금부터" 또는 시작 시각, 채널 사이 간격(기본 25~40분)
4. 채널별 시각·문구를 확인하고 필요하면 고침 (빨간 글씨가 있으면 등록 안 됨)
5. **발행 등록** — 이후는 자동. 알림(macOS)으로 결과를 알려 줍니다

### 명령어

```bash
snspub add "/Volumes/MacData/1. 최종콘텐츠/업로드 예정/영상.mp4" \
  --title "전세금 못 받을 때 임차권등기명령" --caption "소개글" --tags "#전세금 #법률상식" \
  --at "2026-09-28 12:50" --gap 25-40          # --dry-run 이면 미리보기만
snspub list                                     # 발행 현황
snspub show P20260928-a1b2c3                    # 상세 + 기록
snspub retry P20260928-a1b2c3.tiktok            # 실패·확인 필요 작업 다시 올리기
snspub done  P20260928-a1b2c3.naver_clip --url https://...   # 직접 올린 작업 완료 표시
snspub cancel P20260928-a1b2c3                  # 남은 예약 전체 취소
snspub check                                    # 채널 연결 확인
snspub log                                      # 최근 기록
```

작업ID = `게시물ID.채널` (예: `P20260928-a1b2c3.youtube`).

### Claude Code 가 만든 채널별 소개글 가져오기 (JSON)

채널마다 톤을 맞춘 문구를 Claude Code 세션에서 만들었다면 JSON 으로 한 번에 등록합니다.

```bash
snspub import 발행.json --dry-run   # 확인
snspub import 발행.json             # 등록
```

형식은 [examples/post.example.jsonc](examples/post.example.jsonc) 참고 (주석 사용 가능). 여러 개를 한 번에 넣으려면 `{"posts": [ ... ]}`.

- `overrides.<채널>.text` : 그 채널에 **그대로** 올릴 최종 문구 (템플릿·해시태그 자동 추가 없음)
- `overrides.<채널>.caption` / `hashtags` / `title` : 템플릿을 거쳐 조합
- `times.<채널>` : 그 채널만 시각 지정

## 안정성 설계

- **한 작업 = 콘텐츠 1개 × 채널 1개.** 채널마다 따로 실행하고 결과를 따로 기록합니다.
- **자동 재시도는 "게시가 안 된 게 확실할 때"만**: 서버에 닿기 전 연결 실패, 호출 한도(429), 서버 일시 장애.
- **게시가 됐는지 모를 때는 멈춥니다**: 응답 시간 초과, 게시 요청 중 연결 끊김, 프로그램이 올리는 도중 꺼짐.
  단, 플랫폼이 확인 수단을 주는 경우는 확인 후 안전하게 이어갑니다.
  - Upload-Post: `Idempotency-Key` (24시간 안에 같은 키로 다시 보내면 한 번만 게시). **24시간이 지나면 다시 보내지 않고 확인 필요**로 멈춤
  - Instagram: 게시 전·게시 오류 뒤 컨테이너 상태 확인 (PUBLISHED 면 이미 게시됨 → 다시 안 올림)
  - YouTube: 이어올리기 세션으로 받은 바이트 확인 후 나머지만 전송 (영상이 두 개 생기지 않음)
  - TikTok 이 하루 한도로 '초안함'으로 넘어간 경우는 게시 완료로 치지 않고 알려 줌
- **되돌릴 수 없는 요청 직전에 진행 상황을 DB에 먼저 기록**합니다. 프로그램이 죽어도 재시작 때 이 기록으로 판단합니다.
- **등록할 때의 파일 그대로** 올라갑니다 (등록 뒤 파일이 바뀌면 올리지 않음). 같은 파일을 같은 채널에 두 번 등록할 수 없습니다.
- **같은 채널 최소 간격**(기본 60분): Mac 이 꺼져 있다 켜져도 밀린 예약이 한꺼번에 올라가지 않습니다.
- **네이버 카페 글(`{links}`)은 앞 채널이 끝날 때까지 최대 90분 기다렸다가** 유튜브 쇼츠 등의 주소를 넣어 올립니다.
- **보관 이동은 그 원본을 쓰는 다른 발행이 모두 끝난 뒤**에 합니다.
- **실행기는 하나만** 돕니다 (잠금 파일 + 실제 snspub 프로세스인지 확인 → 정전 뒤 남은 잠금 파일에 막히지 않음). 웹 화면은 이 Mac(127.0.0.1)에서만 열리고 다른 사이트의 요청은 거부합니다.
- 비밀키는 `config.jsonc`·`data/` 에만 있고 git 에서 제외됩니다. 로그에는 토큰을 가려서 남깁니다.

---

## 문제 해결

- **"확인 필요"가 떴어요** → 해당 SNS 에서 실제로 올라갔는지 보고, 올라갔으면 [게시됨으로 표시](주소 붙여 넣기), 안 올라갔으면 [다시 올리기].
- **"재연결 필요"** → 채널 화면에서 로그인/토큰 등록을 다시 하고 [연결 확인]. 통과하면 보류된 예약이 자동으로 이어집니다.
- **외장 디스크 파일을 못 읽어요** → 전체 디스크 접근 권한에 node 추가, 외장 디스크 연결 확인 (연결이 끊겨 있으면 자동 재시도).
- **로그** → `data/logs/snspub.out.log`, `data/logs/snspub.err.log` (launchd 실행 시), 화면의 [기록] 탭.
- **다른 Mac 으로 옮기기** → `config.jsonc` 와 `data/` 폴더를 함께 복사.

## 개발

```bash
npm test      # 엔진·어댑터·화면 서버 테스트 (외부 API 는 가짜 fetch 로 검증)
```

```
bin/snspub.js          실행 파일
src/engine.js          예약 실행·재시도·확인 필요·복구·보관 (핵심)
src/store.js           SQLite 저장 (node:sqlite, 외부 패키지 없음)
src/planner.js         등록: 파일 확인·채널별 시각·문구·검사
src/adapters/*.js      게시 경로 (uploadpost, meta, youtube, naver-cafe, manual)
src/server.js, ui/     로컬 웹 화면
src/cli.js             명령어
```

새 게시 경로를 추가하려면 `src/adapters/index.js` 의 규약(supports·check·publish·resume·canResume)을 따르는 파일을 만들고 목록에 넣으면 됩니다.

> 참고: 외부 API 요청 형식은 2026-09 공식 문서·공식 SDK 기준으로 맞췄고 가짜 응답으로 검증했습니다. 실제 계정으로는 아직 게시해 보지 않았으므로, 처음에는 채널마다 1건씩(가능하면 비공개·테스트 게시판) 시험해 보세요.
